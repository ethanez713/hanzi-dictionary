# App

Native Android client (Kotlin/Compose, min SDK 26). Two Gradle modules:

- `core/` — pure-Kotlin, KMP-ready (no Android imports): SQLDelight schema + the
  `HanziRepository` that reads the prebuilt packs and assembles the domain models
  (search, character page, component page). Unit-tested against the real pipeline
  output (`./gradlew :core:test`).
- `androidApp/` — Compose UI (search → character → component navigation), pack
  installation, and Android SQLite driver wiring.

## Data packs (required before building androidApp)

The app bundles `core.db` and `ids.db` in `androidApp/src/main/assets/`. These are
**generated by the pipeline and gitignored** (they're build artifacts, ~28 MB), so a
fresh checkout must produce them before an `androidApp` build:

```
cd ../pipeline
python -m fetchers.fetch_all          # if snapshots not already fetched
python -m pipeline.build
python -m pipeline.package            # writes core.db + ids.db (+ JSONL dump)
cp data/build/core.db data/build/ids.db ../app/androidApp/src/main/assets/
```

`:core:test` reads the packs directly from `../pipeline/data/build/`, so it doesn't
need the assets copy — but it does need `pipeline.package` to have run.

## Build

```
source ~/android-tooling/env.sh   # JDK 17 + Gradle + SDK on PATH (this machine)
./gradlew :core:test              # fast: repository logic against the real pack
./gradlew :androidApp:assembleDebug
```

Debug APK lands in `androidApp/build/outputs/apk/debug/`.

## Design notes

- **Two packs, never merged/ATTACHed.** `ids.db` (cjkvi-ids decompositions, GPL) is
  opened as its own SQLite driver alongside `core.db` (BY-SA/LGPL layer + computed
  layer). ATTACH is deliberately avoided: both Android's SQLiteDatabase and SQLDelight's
  JDBC driver pool connections, and ATTACH doesn't reliably propagate across a pool.
  Keeping them as separate drivers merged in Kotlin also preserves the license-layer
  separation on-device that spec §15 requires.
- **Prebuilt DB, no migrations.** The packs ship at `PRAGMA user_version = 1` matching
  the SQLDelight schema version, so Android's OpenHelper opens them without firing
  onCreate/onUpgrade. SQLDelight is used read-only.
- **FTS5** search index lives in `core.db` (built by the pipeline); the repository
  queries it via a raw driver call rather than through SQLDelight's schema, so the
  virtual table never has to round-trip the generator. Requires device SQLite with
  FTS5 (present on API 26+).
